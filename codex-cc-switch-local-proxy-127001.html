配置出现 127.0.0.1，
正常还是被代理了？

如果 CC Switch 已启动“路由”或“聚合”，127.0.0.1:15721 通常是正常的本地入口。界面显示直连但配置仍指向本地、端口未监听，或 WSL2 无法连接时才需要排查。

更新：2026-10-15 · 已核对 CC Switch 当前中文文档与 OpenAI Codex 配置参考

先别手工改配置：路由运行期间，CC Switch 可能再次写回本地地址。先确认当前是“路由/聚合”还是“直连”。

请求实际上怎么走？

Codex → 127.0.0.1:15721 → CC Switch → 当前 API Provider

127.0.0.1 是本机回环地址，不是远端供应商。只看 Codex 配置无法判断最终线路；应在 CC Switch“用量统计”请求日志中查看“请求模型 → 实际模型”、状态码和转发结果。

三种状态不要混淆

状态地址判断
路由 / 聚合已启动通常是 127.0.0.1:15721正常，本地路由转发
已“回到直连”应写回直连供应商仍是本地地址才需排查
OpenAI 官方登录不应依赖第三方本地路由先回到直连，再走 Codex 登录

15721 是 CC Switch 当前文档中的默认端口；若改过设置，以实际端口为准。

1. 查看端口是否监听

macOS / Linux：

lsof -nP -iTCP:15721 -sTCP:LISTEN

Windows PowerShell：

Get-NetTCPConnection -LocalPort 15721 -State Listen
  • 路由已启动且有进程监听：继续查看请求日志；
  • 路由已启动但没有监听：重启 CC Switch，检查端口冲突或安全软件；
  • 已回到直连：没有本地监听不一定异常，重点看配置是否写回。

2. 找到 Codex 真正读取的配置

OpenAI 官方配置参考说明，用户级配置位于 ~/.codex/config.toml。设置过 CODEX_HOME 时位置会改变；项目内 .codex/config.toml 不能覆盖 model_provider、model_providers 和 openai_base_url 等机器本地 Provider 设置。

同时核对实际 CODEX_HOME、CC Switch 的 Codex 配置目录，以及是否有另一个 Codex 进程仍读取旧配置。

3. 回到直连并彻底重启

点击 CC Switch 的“回到直连”，确认配置写回，再完全重启 Codex。Codex CLI 需要结束仍运行的后台进程；macOS 桌面版应按 ⌘Q；编辑器插件应重新加载窗口。

4. WSL2 是特殊情况

Windows 端 CC Switch 使用本地路由时，WSL2 默认 NAT 模式里的 127.0.0.1 指向 WSL 自己，无法直接连接 Windows 宿主机的本地路由。典型现象是 Windows 端端口正常、WSL 内 Codex 却连接被拒绝。可按 CC Switch 文档改用 mirrored 网络模式。

按现象直接处理

现象处理方向
本地地址 + 日志中有成功请求正常路由，无需修改
本地地址 + 端口未监听重启 CC Switch，检查冲突
直连状态仍是本地地址核对 CODEX_HOME 与配置目录
本地路由通，但返回 401 / 404排查上游 Key、模型和路径
切换后仍使用旧模型完全重启 Codex
