确认用户级配置真的生效

Codex 用户级配置通常位于 ~/.codex/config.toml。如果设置过 CODEX_HOME，实际位置会改变。

如果 CC Switch 把地址写成 127.0.0.1:15721，先阅读本地代理与直连状态排错；路由或聚合模式下这通常是正常设计。

model = "从服务控制台复制的当前模型名"
model_provider = "your_gateway"

[model_providers.your_gateway]
name = "Your Gateway"
base_url = "https://你的网关地址/v1"
env_key = "OPENAI_API_KEY"
wire_api = "responses"
  • 顶层 model_provider 与 Provider 表 ID 必须完全一致；
  • base_url 是否需要 /v1 应以服务商文档为准；
  • 使用控制台当前模型 ID，不要猜营销名称；
  • 不要依赖项目内配置覆盖 Provider 和认证设置。

环境变量可能仍指向旧 Key

配置工具可能只修改端点，而不会清理终端或启动器里已经存在的变量。已经运行的进程也不会自动获得新值。修改后请从同一个终端重启，并避免在截图、Issue 或群聊中暴露真实 Key。

按照状态码分流

  • 401 / 403：Key、鉴权头或模型权限；
  • 404 / model not found：地址、接口路径或模型 ID；
  • 429：余额、并发或限流窗口，避免重试风暴；
  • 502 / 503：固定同一任务，换时间或模型做对照；
  • 固定时长断流：检查 SSE 透传、代理缓冲和空闲超时。

恢复后连续验收 3 次

不要用一句聊天判断稳定性。固定同一个真实仓库任务：先读取入口和测试命令，再修改两个相关文件并运行测试，记录是否完成、重连次数、耗时和实际扣费。
