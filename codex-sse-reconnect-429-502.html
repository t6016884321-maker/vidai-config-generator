三类故障，三个方向

现象优先判断第一动作
429速率、并发或额度限制停止新增并发，检查限流窗口
502 / 503网关或上游无有效响应固定同一任务做分时段对照
固定时长断流SSE 被中间层提前关闭检查缓冲、透传和空闲超时

“3/5”不是任务进度

Codex 的自定义 Provider 可以分别设置普通 HTTP 请求重试、SSE 流重试和流空闲超时。它们用于短暂故障后的恢复，不能修复错误模型名、无权限 Key 或不兼容接口。

[model_providers.your_gateway]
name = "Your Gateway"
base_url = "https://你的网关地址/v1"
env_key = "OPENAI_API_KEY"
wire_api = "responses"
request_max_retries = 4
stream_max_retries = 10
stream_idle_timeout_ms = 300000

不要盲目把重试次数调到很高。错误请求可能因此持续更久，并放大并发和费用。

429：先阻止重试风暴

  1. 暂停新的 Agent、终端和 CI 任务；
  2. 检查余额、账户额度和服务商限流规则；
  3. 等待一个限流窗口后，只跑一个小任务；
  4. 确认是否有后台任务共用同一个 Key；
  5. 恢复后再逐步增加并发。

502 / 503：做三组对照

  • 同一网络、不同时间：判断是否为瞬时上游故障；
  • 同一 Provider、不同模型：判断是否为单模型路由或容量问题；
  • 同一模型、短任务与长任务：判断是否为 SSE 长连接或代理超时。

一次只改变一个变量。如果每次都在接近 60 秒、100 秒或 5 分钟时断开，固定时长本身就是中间层超时的重要线索。

能聊天，不代表能跑真实仓库

Codex 会持续接收流式事件，还会多次读取文件、执行工具并回传结果。至少要验证 Responses API、SSE 持续透传、工具调用闭环、失败重连和用量扣费；一次短问答成功不足以证明稳定。

15 分钟可复现验收

  1. 固定同一个仓库、模型和小型跨文件任务；
  2. 连续执行 3 次，不在中途改变参数；
  3. 记录完成率、重连次数、首响应、总耗时和实际扣费；
  4. 再一次只改一个参数，重新做同样三次测试。
